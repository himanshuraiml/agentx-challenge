Developer Documentation

1. Introduction

Welcome to the developer documentation for the AgentX Challenge. This event is an intensive internal hackathon hosted exclusively at SRMIST Tiruchirappalli for students across all technical departments.

The hackathon is a fast-paced 6-hour sprint taking place on October 30, 2026. Teams will compete to design, implement, and deploy autonomous AI Agent architectures addressing critical problems in one of five target domains: Healthcare, Education, Agriculture, Finance, and Smart Cities.

Key Info: Registration opens on October 10, 2026. Make sure you have submitted your final registration on the Google Form before October 30, 2026. Teams should consist of 1 to 4 members.

2. Free Cloud Models & Colab Setup

You do not need a credit card or paid subscription. We have structured the entire hackathon around high-speed, free cloud API tiers and zero-install options:

  • Google AI Studio: Generate a free API key at aistudio.google.com using your college or personal Google account. Free tier with per-minute and per-day limits.
  • Groq Cloud: Create an instant free key at console.groq.com. Offers very fast inference, handy for multi-step tool loops. Available free models change over time, so pick one your key lists.
  • Google Colab Starter Notebook (Zero Local Install): If your lab PC has restrictions on software installation or slow package downloads, run the starter agent in Google Chrome directly via our Colab template.
Tip for Beginners: Store your API keys in a .env file (or Colab Secrets) and never commit your raw keys to GitHub.

3. Concept of Agentic AI

Unlike traditional AI systems that act as single-turn chat completion wrappers, Agentic AI systems are designed with autonomy. An agent operates within a cyclic execution sequence commonly referred to as the Perceive-Plan-Act loop:

  1. Perceive: The agent takes a user query or environment telemetry as input.
  2. Plan: The agent breaks the complex query down into smaller sub-tasks, choosing which tools are needed and structuring the execution sequence.
  3. Act: The agent invokes tools (running calculations, searching databases, querying APIs) and processes the results to either output a final response or run another reasoning cycle.

The core differentiator is the agent's ability to recursively review outcomes and correct its path when a tool output indicates an error or a search results in empty outputs.

4. Planning & Reasoning

For the AgentX Challenge, your team must implement a robust reasoning mechanism. Common patterns include:

  • ReAct (Reason + Action): For every step, the agent outputs a thought detailing what it plans to do, followed by a specific tool invocation request.
  • Plan-and-Solve: The agent generates a complete multi-step roadmap at the beginning of the execution, and then follows it sequentially while adapting to tool results.
  • Multi-Agent Systems: Multiple specialized agents (e.g. a research agent, a coder agent, and an editor agent) collaborate via structured messaging boundaries to deliver the final response.

5. Tool Integration

Agents interact with the external world using Tools. A tool is a function wrapped in a structured schema that tells the LLM the function name, what it does, and what inputs it accepts.

An example of defining a JSON schema for a weather API tool: 

{
  "name": "get_weather_data",
  "description": "Retrieve humidity and temperature forecast for a specific location.",
  "parameters": {
    "type": "object",
    "properties": {
      "location": { "type": "string", "description": "City and state name" },
      "days": { "type": "integer", "description": "Forecast duration" }
    },
    "required": ["location"]
  }
}

Your project will be heavily scored on how well your agent coordinates tool inputs, validates output types, and recovers from network failures during execution.

6. 3-Round Milestone Judging & Anti-Wrapper Policy

To ensure fairness and encourage genuine technical depth, judging takes place live in the computer labs across three milestones:

  • Round 1: Desk Setup Check (Hour 3): Judges verify that your team has an active environment (or Colab), valid API keys, and at least 1 working custom tool call executing live in the terminal.
  • Round 2: Autonomy & Tool Loop Elimination (Hour 5.5): Judges stress-test your agent with an unseen test query at your lab desk. The agent must demonstrate multi-step reasoning (Thought ➔ Action ➔ Tool Result ➔ Synthesis) with at least 2 distinct tools. The top 6–8 teams are selected for the auditorium finale.
  • Round 3: Grand Finale Stage Pitches (Hour 7): Finalists present a 3-minute pitch, 2-minute live demo, and answer judge Q&A in the auditorium.

Final scoring weights (100 points):

  • Agentic Architecture & Autonomy (40): plans before acting, picks tools dynamically, handles failures and retries.
  • Domain Utility & Execution (30): realistic datasets and APIs, no dummy hardcoded strings.
  • Code Hygiene & System Design (20): separate agent brain, tool registry and execution driver; reproducible repo.
  • Presentation & Live Demo (10): clear demo and confident answers to judge questions.
Anti-Wrapper Policy: Systems that simply forward a user query to a single LLM prompt without an autonomous decision loop, without tool calls, or with hardcoded outputs will be penalized with an automatic ceiling of 40% maximum score.

7. Submission Rules

The build window ends exactly 6 hours after launch. Code freeze is at 03:45 PM. Your submission, sent via Google Form, must include:

  • GitHub Link containing clean source code, dependencies manifest, and setup documentation.
  • System Diagram outlining the planning loops, prompt templates, and database tool nodes.
  • Demo Video (2-minute maximum) showing the agent performing live planning and executing tool calls.

8. Backend Contract (Auto-Judging)

Every submission is tested automatically on hidden data before judges see your frontend. Your repo must be public and follow this contract:

  • python main.py --json "<query>" prints one JSON object to stdout, with logs on stderr.
  • Shape: {"answer": "...", "trace": [{"thought": "...", "tool": "name", "args": {}, "observation": "..."}]}. Every tool call must appear in the trace.
  • Read input files from the folder in the AGENTX_DATA_DIR environment variable, using your theme's file names (for example transactions.csv). Never hardcode paths or answers.
  • Read API keys from GEMINI_API_KEY / GROQ_API_KEY only. A committed key costs hygiene points.
  • Include requirements.txt, a README, and at least 2 tools. Cap your loop (for example max_iterations = 5).
  • If a data file is empty or a tool fails, return a graceful answer instead of crashing.
  • Your frontend may be anything, but it must call this same agent code.
The tests use unseen queries and different data from the public datasets, so hardcoded outputs will fail.
